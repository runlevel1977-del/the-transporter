The Transporter — Installation
==============================

Docker-App für UGREEN-NAS. Kein UGREEN-Entwicklerkonto, keine .upk.

Downloads:
  https://github.com/runlevel1977-del/the-transporter
  Release v0.2.0:
    AMD64  the-transporter-0.2.0-amd64.tar
    ARM64  the-transporter-0.2.0-arm64.tar

NICHT über die UGOS-Docker-Oberfläche "Projekt anlegen".
Host-Netz + privileged werden dort abgelehnt. Start nur per SSH + docker compose.


1) PowerShell auf dem PC — SSH öffnen
--------------------------------------
NAS-IP und Benutzer anpassen (Beispiel: papa und 192.168.2.168).

    ssh papa@192.168.2.168

Passwort eingeben. Ab hier bist du auf dem NAS (Linux).
Die nächsten Befehle in DASSELBE Fenster kleben.


2) CPU prüfen
-------------
    uname -m

  x86_64           = AMD64  (z.B. DXP4800)  -> amd64-Datei
  aarch64 / arm64  = ARM64                  -> arm64-Datei


3) Ordner
---------
    sudo mkdir -p /volume1/docker/the-transporter
    cd /volume1/docker/the-transporter
    pwd

Muss stehen: /volume1/docker/the-transporter


4) YAML laden
-------------
    sudo curl -fL -o docker-compose.yml https://raw.githubusercontent.com/runlevel1977-del/the-transporter/main/docker-compose.yml


5) Volumes einbinden (automatisch)
----------------------------------
Prüft, welche /volume1 … /volume8 auf dem NAS wirklich gemountet sind,
und trägt nur die in die YAML ein. Keine leeren Ordner, kein Handarbeit.

    sudo curl -fsSL -o patch-volumes.sh https://raw.githubusercontent.com/runlevel1977-del/the-transporter/main/patch-volumes.sh
    sudo sh patch-volumes.sh docker-compose.yml

Ausgabe z.B. „Volumes eingebunden: /volume1 /volume2 /volume3“.


6) Port
-------
Standard ist 21011.

Läuft dort schon die Transporter-App (UPK), Port ändern:

    sudo sed -i 's/21011/21012/g' docker-compose.yml

Prüfen:

    grep port docker-compose.yml


7) Image laden (eine der beiden Zeilen, passend zu Schritt 2)
-------------------------------------------------------------
AMD64:

    sudo curl -fL -o /tmp/the-transporter.tar https://github.com/runlevel1977-del/the-transporter/releases/download/v0.2.0/the-transporter-0.2.0-amd64.tar

ARM64:

    sudo curl -fL -o /tmp/the-transporter.tar https://github.com/runlevel1977-del/the-transporter/releases/download/v0.2.0/the-transporter-0.2.0-arm64.tar

Dann:

    ls -lh /tmp/the-transporter.tar
    sudo docker load -i /tmp/the-transporter.tar
    sudo docker image inspect the-transporter:0.2.0 --format '{{.Architecture}}'

inspect muss zu Schritt 2 passen: amd64 oder arm64.


8) Starten
----------
    sudo docker compose -f /volume1/docker/the-transporter/docker-compose.yml up -d
    sudo docker ps --filter name=the-transporter

Status muss Up sein, nicht Restarting.


9) Browser
----------
Port 21011 (oder 21012, falls geändert):

    http://NAS-IP:21011

Beispiel:

    http://192.168.2.168:21011


Kurzform (alles nach dem SSH-Login, AMD64, Port 21011)
------------------------------------------------------
    sudo mkdir -p /volume1/docker/the-transporter
    cd /volume1/docker/the-transporter
    sudo curl -fL -o docker-compose.yml https://raw.githubusercontent.com/runlevel1977-del/the-transporter/main/docker-compose.yml
    sudo curl -fsSL -o patch-volumes.sh https://raw.githubusercontent.com/runlevel1977-del/the-transporter/main/patch-volumes.sh
    sudo sh patch-volumes.sh docker-compose.yml
    sudo curl -fL -o /tmp/the-transporter.tar https://github.com/runlevel1977-del/the-transporter/releases/download/v0.2.0/the-transporter-0.2.0-amd64.tar
    sudo docker load -i /tmp/the-transporter.tar
    sudo docker compose -f /volume1/docker/the-transporter/docker-compose.yml up -d


Kurzform ARM64
--------------
Wie oben, nur die curl-URL auf the-transporter-0.2.0-arm64.tar ändern.


Jobs von der Transporter-UPK übernehmen (optional)
--------------------------------------------------
Nur wenn die UPK-App schon Geräte/Jobs hat. The Transporter kurz stoppen,
Datei kopieren, wieder starten. UPK dabei nicht anhalten.

    sudo docker compose -f /volume1/docker/the-transporter/docker-compose.yml stop
    sudo cp -a /var/packages/com.runlevel.transporter/data/state.json /volume1/docker/the-transporter/state.json
    sudo cp -a /var/packages/com.runlevel.transporter/data/privacy_consent.json /volume1/docker/the-transporter/privacy_consent.json
    sudo docker compose -f /volume1/docker/the-transporter/docker-compose.yml start

Danach Seite neu laden. Laufen UPK und The Transporter parallel mit denselben
Zeitplänen, starten Jobs doppelt — dann in einer der beiden die Jobs aus.


Stoppen / deinstallieren
------------------------
    sudo docker compose -f /volume1/docker/the-transporter/docker-compose.yml down
    sudo docker rmi the-transporter:0.2.0

Ordner optional:

    sudo rm -rf /volume1/docker/the-transporter


Update in der App
-----------------
In der YAML muss stehen:

    - /var/run/docker.sock:/var/run/docker.sock

Danach unten links „Update“: prüft GitHub, bei neuer Version laden und
Container neu starten. Ohne diese Zeile nur Hinweis, kein Selbst-Update.

Falls die YAML schon existiert, Zeile ergänzen und:

    sudo docker compose -f /volume1/docker/the-transporter/docker-compose.yml up -d


Volumes nachträglich (YAML existiert schon)
------------------------------------------
    cd /volume1/docker/the-transporter
    sudo curl -fsSL -o patch-volumes.sh https://raw.githubusercontent.com/runlevel1977-del/the-transporter/main/patch-volumes.sh
    sudo sh patch-volumes.sh docker-compose.yml
    sudo docker compose -f /volume1/docker/the-transporter/docker-compose.yml up -d

Port und übrige YAML-Zeilen bleiben. Nur die /volumeN-Zeilen werden neu gesetzt.


Fehler
------
exec format error / Restarting
  Falsche CPU-Datei (ARM auf AMD oder umgekehrt). Image löschen, richtige
  Datei laden, neu starten.

Vorgang fehlgeschlagen in der Docker-GUI
  Normal. Nicht die GUI, sondern docker compose per SSH.

compose.yml: no such file
  Zuerst cd /volume1/docker/the-transporter — nicht im Home-Ordner bleiben.
